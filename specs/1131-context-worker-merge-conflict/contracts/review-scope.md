## Contract A — `reviewScope` transport (outcome → context)

**Producer**: `MergeConflictHandler.finishSuccess`
**Consumer**: `claude-cli-worker.ts` context-build seam
**Channel**: `ReArmedOutcome.reviewScope` → `rearmItem.metadata.reviewScope` →
`WorkerContext.reviewScope`

### Shape

```ts
type ReviewScope = { readonly baseSha: string; readonly headSha: string };
```

### Producer obligations (`finishSuccess`)

Gated on `config.reviewPhaseEnabled`:

- **Flag ON, merge commit exists**: return
  `{ outcome: 're-armed', startPhase: 'review', reviewScope: { baseSha: HEAD^1,
  headSha: HEAD } }`. `baseSha` = first parent of the `--no-ff` merge (pre-merge
  branch tip); `headSha` = the merge commit.
- **Flag ON, no-op merge path** (no merge commit): return
  `{ startPhase: 'review', reviewScope: { baseSha: HEAD, headSha: HEAD } }` — a
  deliberately empty window.
- **Flag ON, SHAs undeterminable**: return `{ startPhase: 'review' }` with
  `reviewScope` **omitted** (whole-branch fallback, FR-010). Do **not** fail
  loud on missing SHAs.
- **Flag OFF**: return `{ startPhase: metadata.phase }` with no `reviewScope`
  (byte-identical to today, FR-009).

`metadata.phase` MUST still be present for the pre-existing fail-loud guard;
missing `metadata.phase` → `blocked:stuck-merge-conflicts` exactly as today.

### Consumer obligations (context build)

At the seam that already reads `md['resumeReason']` / `md['baseSha']`:

- Set `context.resumeReason = 'merge-conflict-resolved'` when the rearm metadata
  says so.
- **Explicit start-phase override**: when `md['resumeReason'] ===
  'merge-conflict-resolved'` AND `md['startPhase'] === 'review'`, set
  `context.startPhase = 'review'` directly, bypassing the label-derived
  `resolveStartPhase` result. For any other `resumeReason`/`startPhase`, the
  label-derived start phase is used unchanged.
- Set `context.reviewScope = md['reviewScope']` (may be `undefined`).

### Invariants

- Flag OFF ⇒ no override taken ⇒ start phase resolved from labels ⇒
  byte-identical to current behavior. (SC-005 blocked-path regression is
  unaffected — this contract only covers the success re-arm.)
- The re-armed consistency assertion
  (`handler-outcome-assertion.ts:43-56`) stays green because
  `rearmItem.metadata.startPhase === outcome.startPhase` by construction.

## Contract B — charter diff-window (executor → charter)

**Producer**: `ReviewExecutor.execute` (reads `context.reviewScope`)
**Consumer**: `buildReviewCharter(input)` (reads `input.diffWindow`)

### Shape

```ts
interface ReviewCharterInput {
  profile: ReviewProfile;
  sidecarRelPath: string;
  blockingSeverity: Severity;
  round: number;
  diffWindow?: { baseSha: string; headSha: string };  // NEW
}
```

### Executor obligations

Given `context.reviewScope`:

1. **Absent** (`undefined`): call `buildReviewCharter` with no `diffWindow` →
   whole-PR review (FR-010). Proceed to spawn as today.
2. **Present**: run `git diff --quiet <baseSha>..<headSha>` (or
   `--name-only`) in the checkout.
   - **Empty diff** → **short-circuit**: do not spawn the CLI, do not write a
     findings artifact, return a synthetic success PhaseResult so the loop
     advances to `validate` (FR-011, SC-004). The charter's "empty diff =
     blocking finding" rule is **not** applied.
   - **Non-empty diff** → call `buildReviewCharter` with `diffWindow: { baseSha,
     headSha }` and spawn as today.

### Charter obligations

- With `diffWindow` present: name the exact `baseSha..headSha` range as the
  review target, replacing the whole-PR-diff language (FR-002). Everything else
  (profile behavior, forbid tests/builds per FR-007, sidecar write instruction)
  is unchanged.
- With `diffWindow` absent: byte-identical to the current charter.

### Invariants

- FR-005 (validate runs on post-merge state) holds on **every** branch: scoped
  clean review → validate; scoped review with findings → remediate → …
  eventually validate; empty-window short-circuit → validate; whole-branch
  fallback → validate. No success branch reaches merge readiness without
  `validate`.
- FR-007: no build or test process is spawned during the resolution or the
  scoped review (the charter forbids it; the short-circuit spawns nothing).
